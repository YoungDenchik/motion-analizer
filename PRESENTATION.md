## Проблема

- **80% людей** займаються без тренера — і роблять це неправильно
- Неправильна техніка → мікротравми → хронічні ушкодження

- YouTube-відео не дають **персонального** фідбеку
- Спортзали не мають інструменту для масштабованого контролю техніки

## Ключові технічні рішення

### Чому кути суглобів, а не координати?

```
Координати:  залежать від відстані до камери, зросту, ракурсу
Кут суглоба: чистий біомеханічний показник — 90° коліна = 90° завжди
```

### Чому нормалізація по стегнах?

```python
# Переміщення в систему координат центру стегон
hip_center = (left_hip + right_hip) / 2
normalized = (landmark - hip_center) / torso_length
```

Усуває залежність від позиції камери і зросту людини.

### Чому FastDTW замість Euclidean?

```
Euclidean: потребує однакову довжину і часове вирівнювання
DTW:       знаходить оптимальне вирівнювання по часовій осі
FastDTW:   O(N) апроксимація — реальний час для послідовностей до 500 кадрів
```

## Motion Signature — пошук найкращого референсу

### Проблема

У базі є `squat.json`, `squat_lowbar.json`, `squat_front.json`.
Як автоматично вибрати найближчий до відео користувача?

### Рішення: 99-вимірний вектор ознак

Signature обчислюється на **canonical rep** (усереднений повтор),
не на всій сесії — щоб не забруднювати статистику паузами між підходами.

```
Компонент            Розмір   Що кодує
─────────────────────────────────────────────────────────────
mean                   9      Типова постура + проекція камери
std                    9      Амплітуда руху кожного суглоба
p10 / p90             18      Робастні екстремуми (глибина присіду)
skewness               9      Час у нижній / верхній точці
mean_abs_velocity      9      Середня швидкість руху (дег/с)
velocity_asymmetry     9      Частка кадрів де суглоб розгинається
correlations          36      Попарна кореляція суглобів (стиль техніки)
─────────────────────────────────────────────────────────────
TOTAL                 99      float32
```

### Метрика схожості: косинусна відстань

```
sim(u, r) = (u · r) / (‖u‖ · ‖r‖)
```

Масштабно-інваріантна: кут коліна ~120° не домінує над нахилом тулуба ~10°.

## Пошук референсу: алгоритм

```python
def find_best_match(user_ts, exercise):
    # 1. Завантажити всі варіанти вправи
    candidates = load_family(exercise)   # squat, squat_front, squat_lowbar

    if len(candidates) == 1:
        return candidates[0]             # нема вибору — повертаємо єдиний

    # 2. Обчислити signature користувача
    #    (автосегментація → canonical rep → 99-dim вектор)
    user_sig = MotionSignature.from_timeseries(user_ts)

    # 3. Знайти найближчий по косинусній відстані
    best = min(candidates,
               key=lambda r: user_sig.distance(r.signature))
    return best
```

```
[ReferenceStore] 3 variants for 'squat'
  ✓ best match:  'squat'       dist=0.031  ← відео збоку
  ✗ skipped:     'squat_front' dist=0.312
  ✗ skipped:     'squat_lowbar' dist=0.187
```

## Сегментація повторів

### Проблема

Відео містить 3 присідання поспіль — треба автоматично
знайти границі кожного повторення.

### Алгоритм (3 кроки)

**Крок 1 — Сигнал для аналізу (PCA)**

Замість одного суглоба — перша головна компонента всіх 9 ознак.
PCA об'єднує корельовані рухи суглобів і усереднює шум окремих датчиків.

```python
_, _, Vt = np.linalg.svd(centered_data)
pc1 = centered_data @ Vt[0]   # (T,) — домінуюча осциляція
```

**Крок 2 — Multi-scale згладжування**

Три розміри вікна (×1, ×2, ×4 від базового).
Грубіше згладжування прибирає внутрішньоповторні піки.

**Крок 3 — Adaptive prominence sweep + оцінка**

```
score = CV(інтервали між піками) + 0.002 × кількість_піків
```

Серед конфігурацій з однаковою узгодженістю — перевага меншій кількості піків.

---

## Математика сегментації

### Коефіцієнт варіації (CV)

Повтори займають приблизно однаковий час → рівні інтервали → мінімальний CV:

```
CV = σ(intervals) / μ(intervals)
```

Зайвий пік розбиває інтервал навпіл → CV зростає → конфігурація відкидається.

### Функція оцінки кандидата

```
score = CV + 0.002 × N_peaks
```

При рівному CV → перевага меншій кількості піків (принцип Оккама).

### Захист від систематичної помилки +1

**Проблема**: якщо піки потрапляють у нижню точку присідання,
і голова, і хвіст сегменту включаються → N+1 замість N повторів.

**Рішення**:
1. Завжди шукаємо **позитивні** піки (вершини → стоячи), а не від'ємні
2. Поріг включення голови/хвоста: `max(min_frames, 0.6 × median_interior)`

## DTW порівняння з референсом

### Чому не Euclidean?

```
Euclidean:
  User  [A, B, C, D, E]    Потребує однакову довжину
  Ref   [a, b, c, d, e]    і точне кадрове вирівнювання
  Dist  = Σ |Aᵢ - aᵢ|²     Нереалістично для реальних рухів

DTW:
  User  [A, B, B, C, D, E]   Один підхід робиться повільніше
  Ref   [a,    b, c, d, e]   Знаходить оптимальне вирівнювання
  Шлях: (1,1)(2,2)(3,2)(4,3)(5,4)(6,5)
```

### FastDTW з адаптивним радіусом

```
Точний DTW:  O(N²) — нереально для 300 кадрів (90 000 операцій)
FastDTW:     O(N)  — смуга Sakoe-Chiba radius=max(r, 15% × max(T_q, T_r))
```

Адаптивний радіус: при різниці довжин q/ref центрує смугу коректно.

### Вагові коефіцієнти ознак

```python
weights = {
    "torso_lean":        2.5,   # критично для травм хребта
    "left_knee_angle":   2.0,   # критично для травм коліна
    "right_knee_angle":  2.0,
    "left_hip_angle":    1.5,
    "right_hip_angle":   1.5,
    "left_elbow_angle":  1.0,   # менш критично
    ...
}
```

## Толерантна зона референсу

### Проблема

Один еталонний відеозапис = один спосіб виконання.
Але "правильно" — це діапазон, а не точка.

### Рішення: міжповторна дисперсія референсу

Якщо референс містить **N > 1 повторів**:

```python
# Усі повтори ресемплюються до медіанної довжини і стекуються
stacked = np.stack([rep.resample(target_len).data for rep in reps])

canonical  = stacked.mean(axis=0)   # (T_ref, F) — шаблон
tolerance  = stacked.std(axis=0)    # (T_ref, F) — допустиме відхилення
```

### Застосування при порівнянні

```
effective_dev = sign(raw_dev) × max(0, |raw_dev| − tolerance)
```

Відхилення **в межах природної варіативності** еталону → ефективне = 0 → не штрафується.

```
Tolerance:  [ 3°, 5°, 2°, ... ]    (per frame, per joint)
Raw dev:    [ 7°, 4°, 1°, ... ]
Effective:  [ 4°, 0°, 0°, ... ]    ← лише те, що виходить за межі
```

## Оцінка техніки: математика

### Формула оцінки кадру

```
frame_score(t) = 100 × exp(−k × mean_abs_deviation(t))

де:
  mean_abs_deviation(t) = mean(|effective_dev(t, f)| for f in features)
  k = sensitivity = 0.05   (налаштовується)
```

### Оцінка повтору

```
rep_score = mean(frame_score(t) for t in rep_frames)
```

### Агрегована оцінка сесії

```
overall_score = mean(rep_score(i) for i in reps)
```

### Градуювання

| Бали | Оцінка | Значення |
|---|---|---|
| 90–100 | A | Відмінна техніка |
| 80–89 | B | Добре — дрібні уточнення |
| 70–79 | C | Непогано — потрібна практика |
| 60–69 | D | Слабко — фокус на помилках |
| < 60 | F | Серйозні проблеми — рекомендується тренер |

## Класифікація помилок

### Два рівні

```
CRITICAL  — ризик травми      — поріг > 12°
TECHNICAL — ефективність руху — поріг > 8°
```

### Критичні суглоби (вищий штраф у DTW)

```python
CRITICAL_FEATURES = {"left_knee_angle", "right_knee_angle", "torso_lean"}
```

### Направлення помилки

```
Positive deviation → суглоб перерозігнутий (занадто відкритий)
Negative deviation → суглоб недостатньо розігнутий (мала глибина)
```

### Приклад класифікації

```
left_knee_angle:  avg_dev = +37° → CRITICAL (гіперекстензія коліна)
torso_lean:       avg_dev = +16° → CRITICAL (надмірний нахил вперед)
left_hip_angle:   avg_dev = +10° → TECHNICAL (недостатнє відведення)
```

## Фідбек: що і як

### Генерація

Rule-based: `(feature_name, ErrorDirection)` → тренерська репліка

```python
CUES = {
    ("left_knee_angle", POSITIVE): (
        "Don't lock out your left knee",
        "Keep a slight bend at the top."
    ),
    ("torso_lean", POSITIVE): (
        "Keep your chest up",
        "Drive through your heels, brace your core."
    ),
    ...
}
```

### Пріоритизація

```
1. Критичні помилки (> 12°) — перші
2. Технічні помилки (> 8°)  — другі
3. В межах кожного рівня: сортування за величиною відхилення
```

### Що включає звіт

- Загальна оцінка + грейд
- Per-rep розбивка (рейтинг кожного повторення)
- Топ-3 пріоритетних виправлення
- Зведена порада ("Ваш пріоритет: коліно і нахил тулуба")

## Обмеження та слабкі місця

### 1. Чутливість до кута зйомки

```
Збоку:   кут коліна коливається 170° → 90°  (амплітуда ~80°)
Спереду: кут коліна "виглядає" 170° → 130° (амплітуда ~40°)
```

**Поточне рішення**: Motion Signature автоматично знаходить референс
з найближчим кутом зйомки.
**Потрібно**: калібрування за ракурсом або 3D-відновлення пози.

### 2. Окклюзія (перекриття суглобів)

MediaPipe може втратити точки при неідеальному освітленні або ракурсі.
Кадри з низькою `visibility` потрапляють у TimeSeries як шум.

### 3. Тільки 2D кути

Проекція 3D руху на 2D площину — завжди є геометричні спотворення.
Ідеально — стереокамера або IMU-датчики.

### 4. Rule-based фідбек

Поточна система фідбеку — статичні правила. Не враховує контекст
(наприклад, вигин при стомленні vs структурний дефект техніки).

### 5. Якість сегментації

При нерівномірному темпі виконання або нечіткому поверненні в стартову
позицію сегментація може давати зайві або пропущені повтори.

## Додаток B: Ключові інваріанти системи

1. **FEATURE_NAMES — глобальний контракт**
   Порядок списку в `extractor.py` визначає порядок стовпців у КОЖНОМУ масиві
   `(T × F)` у системі. Зміна = зламаний всі збережені референси і весь downsteam.

2. **Сегментація перед DTW**
   `RepComparator` завжди сегментує обидві послідовності і порівнює 1-проти-1.
   Ніколи не викликати `DTWComparator` безпосередньо на повній сесії.

3. **`combined_dtw` — синтетичний об'єкт**
   `RepComparisonResult.combined_dtw` — це конкатенація per-rep результатів
   з ідентичним шляхом вирівнювання. Не використовувати `distance` або `path`
   для per-rep аналізу.

4. **MediaPipe Tasks API — тільки**
   `mediapipe.tasks.python.vision.PoseLandmarker`. Ніколи `mp.solutions.*`
   (відсутній на Windows у MediaPipe ≥ 0.10).

5. **Візуалізація — другий прохід**
   Аналіз зберігає кути, а не піксельні координати.
   Рендеринг повторно запускає детектор у `static_image_mode`.
